## Stoplist methods

**Reviewed:** inspect each collection’s top 50 terms by total occurrences and select common grammatical words with low expected topical discrimination. Decisions and reasons are documented. Potentially meaningful terms such as `flow`, `library`, and `not` are retained.

**Automatic:** include every term satisfying `df/N >= threshold`, where `df` counts documents containing the term and `N` includes all parsed documents. There are no manual exceptions. At the default threshold, this method removes `flow` in CRAN and `library` in LISA.

The main `.stp` outputs use the reviewed lists. Automatic outputs are stored separately for comparison.

## Stemming methods

**Porter:** implement the original 1980 suffix rules, including contextual `y`, measure `m`, and Steps 1a–5b. Each step considers the longest matching suffix. If its condition fails, a shorter matching suffix is not tried. Step 2 uses the original `ABLI → ABLE` rule.

**S-stemmer:** implement Harman’s lighter plural-handling rules, applying the first rule whose suffix and conditions qualify.

Both algorithms cache word-to-stem mappings. Document IDs, token order, repetitions, and empty documents are preserved.

If a raw algorithm result is empty, the file-output pipeline retains the original token and records the fallback. In the supplied collections, this occurs for `s`. The raw Porter function remains unchanged, and the NLTK comparison checks raw results before this fallback.

Tests cover parsing, document counts, tokenization, stopword selection, filtering, comparison indexes, Porter rules, the S-stemmer, and caching.

The whole-vocabulary reference test requires Phase 2 outputs for all five collections. It checks that saved mappings match the current implementation and compares raw stems with:

```python
PorterStemmer(mode=PorterStemmer.ORIGINAL_ALGORITHM)
```

Recorded agreement is **100% for every collection**, with zero mismatches. A mismatch CSV containing only its header indicates no mismatches.

Agreement confirms consistency with the reference algorithm. It does not prove semantic correctness or improved retrieval.

## Data handling

- MEDLINE: retain `.W`.
- CRAN and CISI: retain `.T` and `.W`; ignore other fields.
- CRAN’s title is also present in `.W`; both copies are retained.
- CRAN records 471 and 995 are empty and retain their IDs.
- LISA: retain original IDs, count four identical duplicate records once, and skip seven text lines outside document boundaries with a warning. Conflicting copies raise an error.
- NPL: numeric IDs start records and `/` ends them.

Whitespace normalization preserves text for tokenization. Detailed tokenization rules are documented in `src/text_ops.py`.

## Phase 2 results

ICF is calculated as:

```text
ICF = (M_before - M_after) / M_before
```

It measures vocabulary reduction, rather than actual file-size reduction.

| Collection | M before | Porter M after | Porter ICF | S-stemmer M after | S-stemmer ICF |
|---|---:|---:|---:|---:|---:|
| MEDLINE | 13,494 | 9,905 | 0.2660 | 12,278 | 0.0901 |
| CRAN | 7,776 | 5,141 | 0.3389 | 6,828 | 0.1219 |
| CISI | 10,084 | 6,285 | 0.3767 | 8,760 | 0.1313 |
| LISA | 19,225 | 13,439 | 0.3010 | 16,963 | 0.1177 |
| NPL | 12,170 | 7,972 | 0.3449 | 10,476 | 0.1392 |

Porter reduces vocabulary more than the S-stemmer in all five collections. Retrieval effectiveness will be measured in later phases.

The Phase 2 report documents observed over-stemming and under-stemming examples from LISA.
